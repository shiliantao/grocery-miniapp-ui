# 商超小程序 UI 设计

把品牌内容、购物效率和视觉识别一起设计。默认交付三套真正不同的高保真方案，以及可离线打开的三版 HTML 交互预览；不要只替换主色来冒充不同方案。

## 资源位置

- 设计规范：`references/design-system.md`
- 三版可编辑设计稿：`../../assets/editable-designs/`
- 三版 HTML 交互预览模板：`../../assets/html-preview/`
- 交付检查脚本：`scripts/validate_delivery.py`

参考稿用于继承布局尺度、组件规则和改版经验，不得把参考稿当作新项目的唯一创意来源。品牌名称、商品图片、营销文案与页面细节应按新项目重新组织。

## 默认工作流

### 1. 明确交付范围

从用户要求中提取品牌、目标用户、平台、页面清单、已有设计、必须保留的内容和交付格式。信息不全但可合理推断时直接采用默认值：

- 390 × 844 移动端画布；
- A 鲜绿自然、B 鲜采生活市集、C 邻里速配仓三种方向；
- 首页、分类、商品详情、购物车、结算、订单、个人中心、会员等核心页面；
- 完整项目可扩展为参考模板中的 25 页；
- 可编辑 `.kanva.pptd` + 三版离线 HTML 预览。

设计稿任务必须同时遵循 `kimi-design` 技能；实际 uni-app、iOS、Android 或微信小程序实现还应遵循对应平台技能。不要把静态预览图宣称为可运行小程序。

### 2. 先做三套结构方向

三套方案必须在至少四个维度形成明显区别：信息密度、导航结构、商品陈列、图片比例、标题层级、促销表达、会员呈现、背景与形状语言。禁止只换颜色。

- **A 鲜绿自然**：自然食材、清晰分区、舒展留白，强调新鲜与配送效率。
- **B 鲜采生活市集**：温润浅色背景、实物彩色品类、大图双列商品卡、强促销按钮、黑金会员，强调采购欲望与品质感。
- **C 邻里速配仓**：更深色的配送信息头、较高信息密度、紧凑列表和快速复购，强调下单效率。

若用户指定只改其中一版，保留其他页面、元素与文案，不借机重做整个项目。

### 3. 执行设计

先阅读 `references/design-system.md`。图片优先使用用户提供或来源清晰的商品实拍图；保持宽高比，不拉伸。品类入口必须具有高识别度，促销区必须有明确价格与行动按钮，会员区必须体现等级和权益而非单纯金色装饰。

参考外部界面时提取布局原则和交互模式，再改变构图、组件比例、色彩体系和内容组织；不得逐像素复制第三方产品界面、品牌标识或专有插画。

### 4. 生成三版 HTML 交互预览

1. 将 `../../assets/html-preview/` 完整复制到当前工作区的交付目录，不直接修改插件内模板。
2. 用三套渲染图替换 `previews/a/`、`previews/b/`、`previews/c/` 中的页面图片，保持 `page-1.png` 至 `page-25.png` 命名；页数变化时同步修改 `src/main.js` 的页面清单、总数和边界。
3. 在 `src/main.js` 更新方案名称、说明和代表色；在 `index.html` 更新品牌标题和项目说明。
4. 保留方案切换、页面目录、上一页/下一页、键盘方向键、移动端目录和 URL hash 定位。所有资源使用相对路径，不依赖公网、CDN 或远程脚本。
5. 用户要求可操作的业务原型时，另行实现搜索、分类、规格、购物车、结算和会员等真实状态变化；每个按钮都要有结果，不能把“预览翻页”描述成完整购物功能。
6. 运行：

```bash
python3 scripts/validate_delivery.py <交付目录>
```

检查失败必须修复后再交付。最终提供可直接双击的 `index.html`，也可同时提供 ZIP；不要要求用户先部署公网。

### 5. 最终检查与交付

- 可编辑稿通过对应设计工具的校验和截图检查；
- 三版在结构上有明显差异，而非同版换色；
- 品类图片清晰、颜色分明，促销价格与按钮醒目；
- 热卖楼层与限时抢购保持同一促销色体系；
- 会员卡文字、余额、等级、权益和支付按钮层级明确；
- HTML 离线可用，无远程资源、缺图、死按钮或未完成占位文字；
- 外部图片、字体和图标的来源及使用条件已核查，演示素材不被默认为可商用素材；
- 如实区分可编辑设计稿、静态交互预览和真实业务代码。

交付设计稿时遵循 `kimi-design` 的 `.kanva.pptd` 引用规则；交付 HTML 时给出本地文件链接。除非用户明确要求，不生成演讲者备注或动画。
